# 骑迹 · 外卖配送决策系统

面向园区配送站调度员的课程设计软件：遗传算法解决“这一趟接哪些单”和“这些单按什么顺序送”，同时展示求解过程及重复实验数据。

## 本地启动

在本目录使用 Go 1.26.1 或兼容的新版本执行：

```powershell
go run .
```

默认打开 http://localhost:8081 。可通过 PORT 环境变量修改端口。静态资源按当前工作目录的 web/ 加载，请在本模块目录启动。

## 五分钟演示

1. 点击“载入园区示例”，查看五笔订单及餐箱容量 10。
2. 点击“生成接单建议”。默认种子下得到 B、C、D，容量 10、收入 31 元；动态规划独立给出最优收益 31 元。
3. 展开“查看遗传优化过程”，播放、单步或跳至末代，观察 0/1 编码和收益曲线。
4. 点击“规划这些订单的路线”，再点击“规划配送路线”，查看站点顺序和返站路径。
5. 在“方案分析”选择初始化或编码对照，运行两组、每组五个固定种子的实验。
6. 查看均值、样本标准差、逐次运行数据，导出 CSV 和 PNG。
7. 修改订单或地点，观察旧结果失效；刷新页面验证有效输入的本地恢复。

业务路线保留输入顺序与 GA 结果中较短的方案。案例中可能没有改善，界面如实显示 0%，不编造效果。

## 算法与业务边界

- **背包**：每笔订单不可拆分，容量占用为重量、配送收入为价值、餐箱容量为约束。金额以整数分计算，界面显示元。
- **路线**：统一取餐点出发，所有餐品提前备齐，完成后返站；平面欧氏距离只用于比较，不代表真实道路导航。
- **同址**：坐标相同的订单合并停靠点，关联订单编号保留。
- **小规模**：零笔可接订单返回空建议，一笔订单直接判断；少于三个不同送达点直接计算闭合路线，不模拟无意义的 GA 迭代。
- **最优性**：GA 不保证全局最优；只有接单组合可行且收益等于 DP 最优值时才标注达到容量模型最优。两个阶段不构成时效、收入与路线联合最优。
- 本系统不执行真实派单，不包括骑手端、配送跟踪、实时地图或支付结算。

## 实验设计

TSP 支持排列 / 随机键编码、随机 / 半数最近邻混合初始化。随机键使用均匀交叉及逐基因随机重置，排列编码使用 OX/PMX 及逆转/交换/插入。因此编码比较同时改变适配算子，不能把全部效果差异归因于编码本身。2-opt 可在单次规划中研究，重复实验接口关闭它以控制计算成本。

背包支持独立随机 / 分层初始化，锦标赛 / 排序轮盘赌，单点 / 均匀交叉，位翻转 / 交换变异，以及超容量修复开关。关闭修复的运行若最终结果不可行，会明确失败，不作为可用方案。

重复实验默认种子为 7、17、27、37、47。同组各次配置相同，不同组使用相同种子列表。标准差使用样本标准差 n−1，单次运行记 0；曲线为逐代历史最优值的重复运行均值。CSV 金额单位为分，页面和 PNG 金额单位为元。

允许显式传入 0 交叉率、0 变异率和 0 精英数；省略字段保留原默认逻辑。计算耗时不保证复现，固定种子的解与曲线可以复现。

## API

所有新增接口使用 POST JSON，错误为 HTTP 400 与 `{"error":"说明"}`。

| 接口 | 输入 | 输出 |
|---|---|---|
| /api/dispatch/select | orders、capacity、可选 params | selected、eligible、excluded、income、load、optimalIncome、verifiedOptimal、evolution |
| /api/dispatch/route | depot、points、可选 params | stops、tour、distance、baselineDistance、improvement、usedBaseline、evolution |
| /api/analysis/compare | problem、route 或 selection、groups、seeds | input 快照、unit、groups 统计、各次 runs、meanCurve |

订单结构：`{id,name,x,y,load,income}`。地点结构：`{name,x,y,orderIds?}`。tour 为 stops 的索引排列，业务路线从索引 0 出发，最后返回 0（返站不重复存入 tour 数组）。

比较组：`{name,tsp:完整TSP配置}` 或 `{name,knapsack:完整背包配置}`。页面编辑两组，接口最多八组；每组最多十个不同的正安全整数种子。

请求限制为 1 MiB；单次规划最长 45 秒，比较最长 75 秒。比较总预算为 150 万次个体评估且不超过 3000 万次基因评估。前端取消请求后，后端在迭代边界响应取消。

原 TSP 页面位于 /tsp.html，背包和 CEC 页面仍位于 /experiment.html?problem=knapsack 与 ?problem=cec；原 API 保留。

## 数据保存

有效订单与独立路线输入保存在本机浏览器。计算结果是当前输入的快照；输入变化会标记过期。更换浏览器不会自动同步。不要把浏览器本地保存当作服务器订单数据库。
